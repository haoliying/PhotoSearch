# v3.11.5 · 修复严格档搜不到 · 匹配度口径统一

> 发布日期：2026-11-15 · versionCode 19 · 可直接覆盖安装（签名与历史版本一致）

## 一、用户反馈

> 当设置为匹配度为严格的时候，就检索不到，但查看图片，有的是 90%，也查不到。

即：把「搜索准确度」调到**严格 80%** 后搜索几乎不出结果；可点开照片详情，标签角标明明写着 **90%**，按理说 90% ≥ 80% 应该能搜到，却依然查不到。

## 二、根因定位

用离线探针（复现代码见 `tools/V316Eval.kt` A 组，基于 `ConceptRegistry.prepare` 与 `SearchEngine.search` 真实调用）打印：

```
详情页 LabelChip 显示: 90%  (原始标签置信度)
概念通道 evidence[CAR] = 0.765   (0.45 + 0.35 * 0.9)
全文通道 index.score("car") = 0.775   (0.55 + 0.25 * 0.9)
严格档阈值 = max(基线, 0.80) = 0.80

准确度 50% -> 结果 1 张, 综合匹配度=[77]%
准确度 65% -> 结果 1 张, 综合匹配度=[77]%
准确度 80% -> 结果 0 张
准确度 90% -> 结果 0 张
```

v3.11.4 里同时存在**三套互不相干的百分比**：

| 口径 | 出现位置 | 0.90 置信度标签的值 | 谁在与准确度比较 |
| --- | --- | --- | --- |
| 原始识别置信度 | 照片详情标签角标 `LabelChip` | **90%** | 否 |
| 内部证据分 | `ConceptRegistry.fromMetadata` / `buildSearchIndex` | 0.765 / 0.775 | **是**（`max(基线, 准确度)`） |
| `percentOf(avgScore)` | 列表「综合匹配度」 | 77% | 否 |

端侧标签证据的计算式把置信度压缩到了一个窄区间：

```
概念通道: w = 0.45 + 0.35 × confidence   → 上限 0.45 + 0.35 × 1.0 = 0.80
全文通道: w = 0.55 + 0.25 × confidence   → 上限 0.55 + 0.25 × 1.0 = 0.80
```

**端侧证据的理论上限恰好是 0.80，与严格档阈值 0.80 完全相等**。只有大模型给出的结构化关键词（1.0）与描述（0.9）能超过它。因此：

- 用户没开大模型时，全库几乎没有任何证据能达到 0.80 → **严格 / 极严格档必然返回 0 张**；
- 而用户看到的 90% 是**标签原始置信度**，不是检索用的匹配度，两者根本不在同一刻度；
- 列表里的 77% 又是第三套数，进一步加重困惑。

v3.11.4 交付说明里写的「极严格档可能返回 0 张（纯端侧标签证据上限约 0.8~0.9）属正常现象」，实际上把**严格档也几乎全空**这一设计缺陷当成了预期行为。本版予以修正。

## 三、修复方案：单一综合匹配度

核心不变量：

> **综合匹配度（50~100）既是结果列表展示的数，也是与准确度比较的唯一判定值；≥ 准确度才算匹配。**

### 3.1 重新标定刻度

`MatchAccuracy` 新增：

```kotlin
const val EVIDENCE_CEILING = 0.80f

fun toPercent(score: Float, base: Float): Int {
    val span = (EVIDENCE_CEILING - base).coerceAtLeast(0.01f)
    val normalized = ((score - base) / span).coerceIn(0f, 1f)
    return (50f + 50f * normalized + 0.5f).toInt().coerceIn(MIN_PERCENT, 100)
}
```

以「该通道质量基线 = 50 分、端侧证据上限 0.80 = 100 分」做线性拉伸：

| 原始标签置信度 | 内部证据分 | 综合匹配度 |
| --- | --- | --- |
| 1.00 | 0.800 | 100% |
| 0.90 | 0.765 | 94% |
| 0.70 | 0.695 | 83% |
| 0.32 | 0.562 | 60% |
| 刚过基线 | 0.500 | 50% |
| 大模型关键词 | 1.000 | 100%（clamp） |

于是 0.90 置信度的标签得到 94 分，**严格 80% 与极严格 90% 都能正常查到**；用户看到「90%」的照片不再被 80% 门槛误杀。

### 3.2 判定与展示同源

`SearchEngine` 的改动：

- 通道召回恢复 **v3.11.3 固定质量基线**（概念 0.50 / 全文与多弱证据叠加 0.55 / 同义词扩展 0.62），不再用 `max(基线, 准确度)` 抬高通道门槛 —— 这是「严格档全空」的直接原因。
- `evaluateCondition` 命中时返回该通道的 `percent`（经 `toPercent` 换算），未命中为 0。
- 综合匹配度 = **命中条件**的匹配度按 `condition.weight` 加权平均（未命中条件不计入分母，避免 OR 模式被 0 分拉低）。
- 最终 `pass` 追加唯一终判：`matchPercent >= accuracyPercent`。
- `SearchResult.matchPercent` 直接输出这个数，列表视图展示的也是它。
- `avgScore` 与排序逻辑完全不变。

### 3.3 一致性契约

| 不变量 | 说明 |
| --- | --- |
| 结果匹配度 ≥ 当前准确度 | 所有出现在结果里的照片都满足 |
| 展示值即判定值 | 以展示的匹配度为门槛重跑检索，该照片仍命中（幂等） |
| 匹配度不随档位漂移 | 同一照片在不同档位下（只要都出现）数值相同 |
| 默认 50% 逐位兼容 | `toPercent(score >= base, base) >= 50`，旧版结果一个不少 |
| 单调 | 调高准确度只减少结果，不增加、不放宽 |

### 3.4 豁免保持不变

- 时间 / 地点纯筛选 → `matchPercent = 100`，不受准确度影响；
- **纯排除条件查询**（如「没有汽车」，没有正向条件）→ 按 100% 计并豁免终判，否则 `matchPercent = 0` 会让它在任何档位都返回 0 张；
- 排除条件本身仍固定用引擎基线做否决，不跟随准确度抬高（v3.11.4 的 G4 修复保留）。

## 四、UI 与文案

- 照片详情页标签角标由裸 `90%` 改为 **`置信 90%`**，标题改为「内容标签（角标为识别置信度）」，明确它不是搜索匹配度。
- 设置页说明改为「列表显示的综合匹配度就是与门槛比较的同一个数：显示 90% 就一定通过了 80% 的门槛」，并说明两种刻度不可直接对照。
- 帮助第十四章、关于页版本历史、操作手册第十三/十四章同步更新。

## 五、兼容性与代价

- 默认 50% 与 v3.11.3 / v3.11.4 逐位一致（`quickSearch` 旧调用结果相同，排序不变）。
- 准确度仍是**查询期参数**：调档只重跑一次检索，不重新分析照片、不清空文档缓存、不改动已保存的分析结果，几万张下不卡顿。
- `threshold()` / `meets()` / `percentOf()` / `asFraction()` / `PRESETS` / `summary()` 等 v3.11.4 纯函数全部保留，语义不变，供历史评测与外部调用兼容。
- `V315Eval` 的 H2 断言原为 `matchPercent == percentOf(score)`（v3.11.4 旧展示口径），本版口径升级后改为「结果匹配度 ≥ 当前准确度门槛」，并在注释中记录原因；其余 50 项断言未改、全部通过。

## 八、使用建议

装上后**无需任何操作**，配置沿用上次设置。若之前为了避开严格档全空而退回 50%，现在可以重新调到 **严格 80%**，高置信度标签的照片会正常出现。

要点：

- 列表里的「综合匹配度 XX%」与设置页的「准确度 XX%」可以直接比较；出现的结果必然不低于门槛。
- 照片详情里的「置信 XX%」是识别置信度，**不要**拿它对照准确度，两者刻度不同。
- 极严格 90% 仍可能返回 0 张（全库没有综合匹配度 ≥ 90 的照片），退回 80% 或 65% 即可。
- 想找更多照片请开「本地准确度增强」或让大模型补充描述，调低准确度不会放宽召回。
